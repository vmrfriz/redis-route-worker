# API

Публичные импорты:

```python
from redis_route_worker import QueueRoute, RedisWorker, TaskContext
```

## QueueRoute

```python
QueueRoute(queue, event, complete_event, handler, workers=1)
```

| Параметр | Значение |
| --- | --- |
| `queue: str` | Уникальное в данном воркере имя очереди |
| `event: str` | Входное Pub/Sub-событие |
| `complete_event: str` | Событие при вызове `complete()` |
| `handler: Callable[[str, TaskContext], None]` | Синхронный обработчик задания |
| `workers: int = 1` | Положительное целое число потоков маршрута |

Имена должны быть непустыми строками. Некорректные значения вызывают
`ValueError`, невызываемый обработчик — `TypeError`. Маршрут неизменяемый.
Регистрировать маршруты во время работы нельзя.

В качестве `handler` подходят функция, связанный метод экземпляра или вызываемый
объект. Тяжёлые зависимости инициализируйте до `run()`, передав связанный метод:

```python
service = MyService()
route = QueueRoute("jobs", "newJob", "jobDone", service.process, workers=1)
```

## RedisWorker

```python
RedisWorker(routes, prefix="redis_worker", host="localhost", port=6379)
```

`routes` — непустой iterable объектов `QueueRoute`. Повторяющиеся `queue`
и пустой `prefix` отклоняются до подключения. Конструктор не открывает соединение.

Текущий интерфейс подключается к Redis DB 0 по TCP через `host`/`port`, без
параметров ACL, пароля, TLS, Sentinel или Cluster. Префикс изолирует ключи
разных приложений; явно задавайте его для каждого проекта.

### run() -> None

Блокирующий запуск. Подписывается на каналы, создаёт пулы, читает задания и
уведомления. Один экземпляр можно запустить только один раз: повторный запуск
вызывает `RuntimeError`. Ошибки транспорта выходят из `run()` после освобождения
ресурсов. Ошибки обработчика перехватываются и возвращают задание в очередь.

В главном потоке временно устанавливаются обработчики SIGINT/SIGTERM;
предыдущие обработчики восстанавливаются при выходе.

### stop() -> None

Потокобезопасный запрос остановки. Сам вызов не ждёт: ожидание активных
обработчиков и закрытие соединений выполняются внутри завершающегося `run()`.
Экземпляр после остановки повторно не используется.

## TaskContext

Создаётся воркером отдельно для каждого задания. Не конструируйте его вручную
и не сохраняйте для использования после завершения обработчика.

### execution_duration() -> float

Время в секундах от начала выполнения текущего задания, измеренное монотонными
часами. Не включает время ожидания в очереди.

### complete(data: str = "") -> None

Добавляет строку в список результатов маршрута и публикует его `complete_event`
в одной транзакции MULTI/EXEC. JSON автоматически не кодируется:
используйте `json.dumps()` или сериализатор приложения.

Событие завершения задаётся маршрутом, а не результатом конкретного задания.
Если обработчик самостоятельно перехватил ошибку и вызвал `complete()` с описанием
ошибки, пакет опубликует то же настроенное событие. Семантику содержимого результата
определяет приложение.

При исключении после успешного `complete()` исходное задание всё равно
возвращается в очередь. Повторный запуск может создать повторные результаты.
